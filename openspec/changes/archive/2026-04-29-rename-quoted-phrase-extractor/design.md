## Context

Two unrelated tokenizer/evaluator components both want the name `PhraseExtractor`:

- The existing **internal** `struct PhraseExtractor: TokenExtractor` in `Sources/SearchExpressionParser/Tokenization/TokenExtractor/` consumes a `"..."` literal from a `TokenCharacterBuffer` and produces a `Phrase` token. It is purely a tokenization-stage component.
- A planned **public** `struct PhraseExtractor: ExpressionEvaluator` (in the unrelated `builtin-evaluators` change) walks an already-parsed `Expression` tree and returns `[String]` of positive containment phrases for highlighting.

Two top-level types with the same name in the same Swift module is a compile error. One must be renamed before the new evaluator can land.

## Goals / Non-Goals

**Goals:**
- Free the bare name `PhraseExtractor` for the new public evaluator.
- Pick a new name for the tokenizer that accurately describes what it does (extracts a quoted-phrase literal from input characters).
- Keep all existing tokenizer behavior identical — pure rename, no logic change.
- Keep the test suite green throughout: 241/241 before, 241/241 after.

**Non-Goals:**
- Add the new `PhraseExtractor` evaluator (that is `builtin-evaluators`).
- Refactor any tokenization logic.
- Promote the renamed type to `public`.
- Update auto-generated spec metadata (header, Technical Notes) — those are regenerated by `spec-gen`.

## Decisions

**Rename target: `QuotedPhraseExtractor`.** Considered alternatives:

- `PhraseTokenExtractor` — accurate (it is a `TokenExtractor`) but every neighbor in the directory already conforms to `TokenExtractor`; the protocol suffix is redundant.
- `QuotedStringExtractor` — accurate but loses the `Phrase` tie-in. The token type produced is `Phrase`, so keeping "Phrase" in the name preserves the input-to-output mapping.
- `QuoteExtractor` — too vague; could mean a single quote character.

`QuotedPhraseExtractor` reads truthfully ("extract a phrase delimited by quotes") and matches the directory's existing prefix style (`AndExtractor`, `OrExtractor`, `BangExtractor`, `NotExtractor`).

**Pure rename, no behavior change.** The implementation stays byte-for-byte identical except for the type name. Tests should not need new assertions, only updated identifiers.

**Test strategy.** TDD doesn't apply cleanly to a rename — there is no "red" state to introduce, since the existing tests already cover the behavior under the old name. The discipline here is regression-focused: run the full suite before, perform the rename in a single logical commit, run the full suite again, confirm the count and outcomes are identical.

**Delta specs cover only requirement-level mentions.** The four affected main specs all currently reference `PhraseExtractor` by name in either requirement text or scenario text. Each gets a MODIFIED requirement block in this change's delta specs that republishes the entire block with the new name. Auto-generated headers and Technical Notes sections are non-requirement metadata and are not part of the delta — they will resolve at the next `spec-gen` regeneration.

## Risks / Trade-offs

**Risk:** missed reference somewhere in the repo causes a build break. → **Mitigation:** ripgrep for `PhraseExtractor` after the rename and verify every hit either points to the new evaluator (in `builtin-evaluators`, not yet landed) or is a spec-text reference covered by the delta specs. Build + full test suite must stay green.

**Risk:** Xcode project file (`.pbxproj`) references the old filename and breaks the IDE workspace. → **Mitigation:** include `xcodeproj` in the rename's grep sweep; `git mv` the file so SPM and Xcode pick up the rename consistently.

**Trade-off:** the `quoted-phrases` and `overview` main specs will briefly carry stale source-file paths in their auto-generated headers / Technical Notes until `spec-gen` runs again. Acceptable because (a) those sections are not requirement-bearing and (b) the next `spec-gen` cycle reconciles them automatically.

**Risk:** future contributor confusion if both names appear in the codebase during the brief window where `builtin-evaluators` has been merged but a stale checkout of this change still uses the old name. → **Mitigation:** land this change before `builtin-evaluators`. Order matters; document the dependency in `builtin-evaluators` if needed.
